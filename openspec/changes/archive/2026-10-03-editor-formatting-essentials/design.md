## Context

The document editor uses TipTap (ProseMirror) for rich text editing, with HTML as the interchange format between frontend and the Rust conversion pipeline (wo-x2t). Currently 5 TipTap extensions are registered (StarterKit, Underline, TextAlign, Link, Image), providing only basic formatting. The toolbar in HomeTab.tsx has visible buttons for ~15 features but only ~10 are wired to working commands.

The architecture uses a command bridge pattern (`rte-command.ts`) where toolbar buttons dispatch `RichTextCommand` strings through a module-level editor reference. Adding a new formatting feature requires: (1) install TipTap extension, (2) register in RichTextEditor.tsx, (3) add command handler in rte-command.ts, (4) add toolbar button in HomeTab.tsx.

The backend wo-html model (`core/crates/wo-html/src/model.rs`) supports all the formatting we're adding on the frontend except for inline CSS properties (color, highlight, font-family, font-size). The docx→html and html→docx converters in wo-x2t preserve content through intermediate HTML.

## Goals / Non-Goals

**Goals:**
- Add subscript and superscript formatting
- Add text color and highlight (background color)
- Add font family and font size selectors
- Add clear formatting (remove all marks)
- Add blockquote and code block support
- Add justified text alignment
- Add task list (checklist) support
- Add undo/redo toolbar buttons
- Wire all existing HomeTab placeholder buttons (font size, color, highlight, indent)
- Extend backend wo-html model to support inline CSS styles for roundtrip preservation

**Non-Goals:**
- Tables (Phase 2)
- Images/links from Insert tab (Phase 3)
- Headers/footers, page layout (Phase 4)
- Comments, track changes, collaboration (Phase 5)
- Other editor apps (spreadsheet, presentation, PDF, visio)
- Backend conversion of newly supported formatting from/to DOCX/ODT (separate change)
- Font size discrete values (only relative increase/decrease, not a full picker)

## Decisions

### 1. TipTap extension selection
**Chosen**: `@tiptap/extension-subscript`, `@tiptap/extension-superscript`, `@tiptap/extension-color`, `@tiptap/extension-highlight`, `@tiptap/extension-font-family`, `@tiptap/extension-text-style`, `@tiptap/extension-task-list`, `@tiptap/extension-task-item`
**Rationale**: Official TipTap extensions maintained by the TipTap team, consistent API, well-documented. All are ^3.27.1, matching existing extensions.
**Alternatives considered**: Custom ProseMirror plugins — would work but require more code and maintenance for features that already exist as maintained packages.

### 2. Font size implementation
**Chosen**: Use CSS `font-size` via TextStyle extension (same mechanism as font-family), with toolbar buttons for increase/decrease by standard increments.
**Rationale**: No official `@tiptap/extension-font-size` exists at ^3.x. The TextStyle extension's `setFontSize` command is deprecated. We implement via custom extension or direct `setMark('textStyle', { fontSize })`.
**Alternative**: Third-party `@tiptap-pro/extension-font-size` — requires TipTap Pro subscription. Not acceptable.

### 3. Text color and highlight storage
**Chosen**: TipTap stores these as `style` attribute on a `textStyle` mark — e.g., `<span style="color: red">text</span>`.
**Rationale**: This is consistent with how TipTap's Color and Highlight extensions work out of the box.
**Backend implication**: wo-html's `InlineElement::Text` needs an optional `style: Option<String>` field to preserve these during roundtrip.

### 4. Backend model extension approach
**Chosen**: Add an optional `style` field to `InlineElement::Text` in wo-html. The parser extracts `style` attributes from `<span>` tags, the serializer outputs them back. No semantic understanding of CSS properties is needed — just pass-through.
**Rationale**: Minimal change, full roundtrip preservation. DOCX→HTML conversion will produce inline styles when the source has formatting attributes; HTML→DOCX conversion will need separate work (non-goal for this change).
**Risk**: Pass-through styles may produce invalid CSS if generated by arbitrary DOCX files. Mitigation: limit to `color`, `background-color`, `font-family`, `font-size` properties during parser extraction.

## Risks / Trade-offs

- **[Extension collisions]** Selecting both TextAlign and Color may cause attribute merge issues on marks. → Mitigation: Test that `color` and `font-family` marks coexist with alignment marks.
- **[Font size UX]** Without a dropdown picker (only +/- buttons), users can only cycle through increments. → Acceptable for Phase 1; full picker can be added later.
- **[Backend roundtrip]** DOCX files with color/highlight/font info will strip styling on save because wo-x2t converters don't pass through inline styles yet. → Documented non-goal; content is preserved (just loses styling metadata) until backend is updated.
- **[Task list backend]** Task list is an ODF/OOXML feature not supported by wo-x2t converters. → Task lists will work within the editor session but won't survive save/reload. Acceptable for Phase 1; backend support is a follow-up.
