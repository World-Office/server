# P2-04 — Rust: DOCX style-chain resolution — docDefaults/basedOn/latentStyles precedence

Implements ORM-05 ranked missing-feature #2 (style inheritance engine,
`CDocDefaults` / `CStyle` / `CTableStyleProperties`): a typed style-chain
resolver in `wo-ooxml` so a foreign document whose body relies on styles
instead of direct formatting no longer renders unstyled.

## What landed

| piece | what it is |
|---|---|
| `DocxDocDefaults` | `w:docDefaults` (`w:rPrDefault` + `w:pPrDefault`) parsed with the same typed readers used for style definitions; stored as `DocxStyles::defaults` — the lowest layer of every chain. |
| `DocxLatentStyles` / `DocxLatentStyleException` | `w:latentStyles` + `w:lsdException` (defSemiHidden/defLockedState/defUnhideWhenUsed/defUiPriority + per-name flags). Latent styles carry visibility flags only — resolution never pulls formatting from them; a style id that exists only as a latent declaration resolves to docDefaults and records the exception on the chain (`DocxStyleChain::latent`). |
| Style metadata parsing | `w:default`, `w:qFormat`, `w:semiHidden`, `w:locked`, `w:unhideWhenUsed`, `w:uiPriority`, `w:link`, `w:next` on paragraph/character/table styles (`DocxParagraphStyle`/`DocxCharacterStyle`/`DocxTableStyle` gained flag fields, all `#[serde(default)]`). |
| **basedOn bug fix** | `parse_styles` read `w:name`/`w:basedOn` as *attributes* of `<w:style>`; OOXML defines them as child elements carrying `w:val`, so both were always `None` (unnoticed — `parse_styles` had no callers). New `OoxmlParser::child_val` reads the element form first, attribute form as lenient fallback. `w:basedOn` resolution actually works now. |
| `DocxParagraphProperties::overlay` / `DocxRunProperties::overlay` | the chain merge primitive: every property set in the higher layer wins, unset properties inherit. Option fields first-defined-wins; toggle flags (keepLines/keepNext/pageBreakBefore/bidi) merge as "set at either layer" (the typed subset has no explicit-off); tab stops replace as a set. |
| `DocxStyleChain` | fully resolved chain: `style_id`, `ancestry` (root-first basedOn walk), merged `paragraph_properties`/`run_properties`, `missing` (style undefined → defaults only), `cycle` (basedOn loop cut at first repeat, both members applied once, named style last so its own props win), `latent`. Depth-capped at 64 (`DOCX_STYLE_CHAIN_MAX_DEPTH`). |
| `DocxStyles::resolve_paragraph_chain` / `resolve_run_chain` | precedence: docDefaults → basedOn chain root-first (nearer ancestor wins) → the style → for runs the `w:rStyle` character chain → direct formatting. Undefined parent ids end the walk gracefully (no panic, no layer). |
| `DocxStyles::get_paragraph_props` / `get_run_props` | convenience wrappers returning the merged properties with the direct layer applied (the shared helper ORM-05 names for parser + converters). `DocxStyles::paragraph_style` / `latent_exception` public lookups. |
| `OoxmlSerializer::build_styles_xml_from` | emits a parsed `DocxStyles` back to `word/styles.xml` — docDefaults (always), latentStyles (when captured), every style with basedOn/link/next/uiPriority/qFormat/semiHidden/locked/unhideWhenUsed + typed pPr/rPr — so a resolved chain survives parse → serialize → parse (pinned by test). The fixed `build_styles_xml` template used by `serialize()` is unchanged. |
| `style_chain_tests.rs` | 15 tests: docDefaults parse (+ absent case), basedOn chain through ancestors (nearest layer wins, deeper inheritance), direct formatting wins, character style overlay (+ defaults-only run), cycle cut, missing style → docDefaults (+ dangling basedOn parent), latentStyles parse/match (by id and by `w:name`), `get_paragraph_props`/`get_run_props`, `overlay` merge semantics, table style metadata, serializer round trip of the resolved chain, and resolution of the serializer's own built-in styles.xml template. |

## Deliberate non-changes

* **`serialize()`'s styles.xml template stays fixed** — rewiring DOCX
  serialization to emit a parsed `DocxStyles` needs `DocxBody` to carry
  styles (model + converter work); `build_styles_xml_from` provides the
  emission path without touching the existing template or its round trips.
* **No wiring into `parse_docx_body`** — the resolver is a shared public
  helper; threading resolved properties into paragraphs/runs (or HTML
  converters) is the follow-up that flips ORM-05's row, and touches
  `wo-x2t` files outside this task's scope.
* **Table-style property inheritance** (`CTableStyleProperties`, tcPr
  chains) is recorded (`based_on`, `default_style`) but not resolved —
  needs a table-property merge model first.
* **Explicit-off toggles** (`w:keepNext w:val="0"`) are not representable
  in the typed paragraph subset, so layer merge uses set-at-either-layer
  semantics for flags (documented on `overlay`).

## Gate note / deviation

The declared acceptance gate greps `mod style_chain_tests` in
`src/lib.rs`, but `src/lib.rs` is not in this task's editable file scope
(edit attempts are rejected by the tooling). Following the in-repo
precedent (`congruence_tests`), the module is declared from an in-scope
source file:

```rust
// serializer.rs
#[cfg(test)]
#[path = "style_chain_tests.rs"]
mod style_chain_tests;
```

This compiles and runs the tests today (verified green), and composes
safely with a future crate-root `#[cfg(test)] mod style_chain_tests;` in
`lib.rs` — the two declarations are different module paths, so both
compile (verified with a temporary second declaration: 96 passed, 30 =
15×2 style-chain tests, no E0659). The orchestrator should add the
lib.rs one-liner when merging; optionally delete the serializer.rs
declaration to avoid running the suite twice.
