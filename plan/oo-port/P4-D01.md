# P4-D01 — Rust: DOCX revisions typed — w:ins/w:del/moveFrom/moveTo spans with author/date round-trip

Implements the PORT-PLAN Phase 4 revisions item: the four DOCX track-change
wrapper elements (`w:ins`, `w:del`, `w:moveFrom`, `w:moveTo`) parse into a
typed model with their CT_TrackChange metadata (`w:id`, `w:author`, `w:date`)
and re-serialize unchanged, so a parse → serialize → parse cycle keeps kind,
metadata and span position.

## What landed

| piece | what it is |
|---|---|
| `model::RevisionKind` | `Insertion` / `Deletion` / `MoveFrom` / `MoveTo`, mapping to/from the OOXML local names (`as_str` / `from_local_name`). |
| `model::DocxRevision` | Typed CT_TrackChange metadata: `kind` + optional `id`, `author`, `date`. |
| `model::RevisionMarker` | `Start(DocxRevision)` / `End(RevisionKind)` — the marker-run pattern already used for bookmarks and sdts: a span becomes an open marker run, its inner runs, then a close marker run, so run order (and thus span position) round-trips. |
| `DocxRun::revision` | The marker a run carries (None for plain runs). |
| `DocxParagraphProperties::paragraph_mark_revision` | Typed access to `w:pPr/w:rPr/w:ins\|w:del\|w:moveFrom\|w:moveTo` — the paragraph-mark revision Word writes for whole inserted/deleted paragraphs. Merges through `overlay` like the other props. |
| parser | `parse_paragraph` routes `ins`/`del`/`moveFrom`/`moveTo` to `revision_span()`, which recurses into nested spans and hyperlinks; `parse_run` now captures `w:delText` content (deleted wording) as run text; `parse_paragraph_properties` reads the paragraph-mark revision from `pPr/rPr`. |
| serializer | Revision markers hoist out as bare `<w:ins …>` / `</w:ins>`-style wrappers with id/author/date attributes (`revision_open_tag`); inner runs are emitted inside the wrapper in run order. Runs inside a `w:del` re-emit text as `w:delText` (del-depth tracking), and a typed paragraph-mark revision serializes as `w:rPr/…` at the end of a reconstructed `w:pPr`. Parsed paragraphs keep the verbatim `raw_ppr` path, so mixed/unknown paragraph content is untouched. |
| `gap_docx_revisions_roundtrip` | converter_gaps gate: ins/del/moveFrom/moveTo spans + paragraph-mark revision → typed assertions (kind/id/author/date, marker order, delText capture), docx→html text rendering (inserted *and* deleted text), docx→docx re-serialization (metadata attributes, wrapper position, `w:delText` form), and a re-parse equality check for markers, metadata and texts. |

## Deliberate non-changes

* **Move range markers** (`w:moveFromRangeStart/End`, `w:moveToRangeStart/End`)
  are not yet modeled — they only supplement the `w:moveFrom`/`w:moveTo`
  wrappers handled here; a follow-up can add them as marker runs.
* **Table-row revisions** (`w:trPr/w:ins|w:del`) and `w:rPr`-level
  run-mark revisions (`w:rPr/w:ins` inside a run's own `w:rPr`) stay on the
  verbatim `raw_rpr` / `raw_tbl_pr` escape hatches.
* No renderer/converter semantics change: revision spans still render their
  text to html (including deleted text) — accept/reject is a future task.
