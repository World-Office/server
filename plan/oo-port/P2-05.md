# P2-05 — Rust: DOCX data-driven numbering — all abstractNums, foreign parts, gap_numbering_foreign_roundtrip

Implements ORM-05 ranked missing-feature #5 (numbering round-trip,
`CNumbering`/`CAbstractNum`/`CLvl`/`CNum`): a typed, data-driven
`word/numbering.xml` pipeline in `wo-ooxml` so a foreign document keeps its
own numbering definitions (any numFmt, any level text, lvlOverrides) instead
of collapsing to the fixed 8-abstractNum template.

## What landed

| piece | what it is |
|---|---|
| `DocxNumbering` / `DocxAbstractNum` / `DocxNum` / `DocxNumLevel` / `DocxLvlOverride` | the typed numbering model (`model.rs`), all serde-default so old stored bodies deserialize. Level captures `w:ilvl`, `w:start`, `w:numFmt`, `w:lvlText`, `w:lvlJc`, `w:lvlRestart`, `w:pStyle`, `w:suff`, `w:isLgl` and the level's own `w:pPr/w:ind` (left/hanging/firstLine); abstractNum captures `w:multiLevelType`/`w:name`/`w:styleLink`/`w:numStyleLink`; num captures the `w:abstractNumId` link + per-level `w:lvlOverride`/`w:startOverride`. |
| Resolution helpers | `DocxNumbering::num` / `abstract_num` / `abstract_num_for` / `level_for` (OO rule: a level above the last defined one continues the deepest definition — exact miss falls back to the closest lower level) / `start_override`, `DocxNumLevel::is_bullet`. |
| `DocxBody::numbering` | `Option<DocxNumbering>`, captured by the parser whenever `word/numbering.xml` exists. |
| `OoxmlParser::parse_numbering` | reads every `w:abstractNum` (with all its `w:lvl` children) and every `w:num` (abstractNumId + lvlOverride/startOverride) out of `word/numbering.xml`; `None` when the part is absent/unparseable. |
| `OoxmlSerializer::build_numbering_xml_from` | data-driven emission: re-emits exactly what was parsed — every abstractNum with metadata + typed levels, every num with its overrides — so foreign numbering survives parse → serialize → parse (typed-equality pinned). The old fixed 8-template (`build_numbering_xml`) stays as the html→docx fallback, and its numFmt values were synced with the documented wo-x2t registry (2 decimal, 3 lowerAlpha, 4 lowerRoman, 5 upperAlpha, 6 upperRoman, 1/7/8 bullets) — previously 2–6 all emitted `decimal`, so the "wo-x2t keeps this in sync" comment was untrue. |
| Part/rels/content-types gating | `word/numbering.xml` + its Override + `rIdNum` relationship are emitted when `body_uses_numbering()` **or** a non-empty numbering part was parsed (a captured part survives even if no body paragraph references a numId). Documents without lists keep the exact old byte shape. |
| `css_for_num_fmt` (wo-x2t) | docx→html list mapping now resolves numId → abstractNum → level first (through the parsed numbering), deriving ordered/unordered + css list-style-type straight from `w:numFmt` (decimal/lowerLetter/upperLetter/lowerRoman/upperRoman, bullet glyphs → disc/circle/square, none, and Word counting formats like ordinal → ordered with default css). The fixed numId 1..8 registry stays as fallback for hand-built bodies, then the ListNumber style heuristic. Foreign numIds stop collapsing to body text. |
| `gap_numbering_foreign_roundtrip` (converter_gaps.rs) | foreign numbering.xml (abstractNum 100 hybridMultilevel upperRoman/lowerLetter with ind + masks, abstractNum 200 lowerLetter, abstractNum 300 ordinal + isLgl, num 42→100 with `startOverride 5`, numId 43/44) verified three ways: (1) typed parse holds all definitions, (2) docx→docx re-serialization re-emits them and re-parses to typed equality (pre-P2-05 this collapsed to the decimal|bullet template), (3) docx→html renders `<ol style="list-style-type:upper-roman">` / `lower-alpha` from the foreign numFmts. `docx_from_parts`/`zip_entry` helpers added; `docx_from_document_xml` delegates to the new helper. |
| 4 wo-ooxml tests (parser.rs) | foreign parse (levels, metadata, overrides, helpers), foreign round trip (typed equality after serialize), template fallback (registry-synced numFmts), emit-without-body-reference (part + Override + rel still emitted). |
| ORM-05 ledger | `ooxml-docx.md`/`.json` Numbering.cpp/CAbstractNum/CLvl/CNum rows → full (untyped tail noted: numPicBullet, `w:rPr` inside `w:lvl`), summary counts updated (32 full / 46 partial / 115 missing), INDEX.md headline updated. |

## Deliberate non-changes

* **numPicBullet / `w:rPr` in `w:lvl`** — picture bullets and level run
  formatting stay untyped (needs an image-binding model; noted in the
  ledger rows).
* **`w:startValue` vs `w:startOverride`** — html `<ol start>` still comes
  from the per-paragraph `w:startValue` only; the numbering-level
  `startOverride` is preserved through round trips but not yet folded into
  the html numbering start (separate consumer decision).
* **`build_numbering_xml` template ids** — unchanged (1..8); only the
  per-id numFmt strings were corrected to match the css registry that
  wo-x2t already documented.
* **Nested/`numStyleLink` style indirection** — captured on the model but
  `abstract_num_for` resolves only the direct `w:num → w:abstractNumId`
  link; style-link chasing needs the numbering-style part model first.
